# 首枪闪光与精确剪接

用于用户明确要求删去站定射击中“第一枪到击杀之间”的过程。默认自然、利落模式仍按原流程使用。这一流程由 Agent 复核画面并调用现有渲染器；当前引擎没有自动站定判定或枪口闪光检测器。

## 找到正确的起止画面

- **首枪：** 以本人的枪口第一次出现开火闪光为准，对照前一帧确认从无到有。枪口位置随左右持枪、武器皮肤和画面布局变化，先看实际画面再选区域；不要把敌方枪火、弹道或环境亮光当作本人首枪。
- **站定：** 结合交火前后的场景位移与小地图位置核实。小幅瞄准调整和后坐力不等于走动；单凭准星不动或枪口位置不动不能确定站定。证据不足的片段保留原动作。
- **同一次交火：** 回看最后一轮连射之前的点射。短暂停枪后再次开火，可能仍属于同一次站定交火；弹药变化给出的 `burst_start` 只作线索。起点不能跨过前一次击杀或移动、转场等不同片段。
- **击杀：** 核实本人的击杀记录或中央击杀标记第一次出现的画面，保留提示动画的起始帧。模板完全匹配往往晚几帧，`Kill.time` 只用于定位附近画面，不能直接当作最早反馈帧。

## 帧号与时间戳必须对应同一张画面

本次实测中，名义 60 FPS 的录像仍有时间戳偏移。OpenCV 的 `CAP_PROP_POS_FRAMES` 随机跳转取帧出现过 1 帧偏移，前后方向均有；因此不要把跳转请求的帧号直接写成精确切点。

对短录像，从头顺序 `read()` 解码，以 0 开始编号；将同一顺序的画面与 ffprobe 的显示时间戳对应。生成图集时标注这个真实帧号和时间。长录像需要局部定位时，可先定位关键帧，再按解码后的 PTS 对齐目标，不能用“请求的起始帧号 + 循环次数”代替验证。

```text
ffprobe -v error -select_streams v:0 -show_frames -show_entries frame=best_effort_timestamp_time -of json "VIDEO_PATH"
```

确认解码帧数与时间戳列表一致。方案时间轴使用 `best_effort_timestamp_time - media.origin`；不要用 `帧号 / 名义 FPS`，也不要擅自减去第一张视频帧的时间，否则会改变与音频的相对位置。

分析时只缓存候选窗口或缩小后的画面。逐帧比对需要重复访问时，先将这些候选帧读入内存，避免反复解压整张高清帧或保存整段视频的无用帧数组。

## 生成可复用的方案

设 `F` 为首次枪口闪光的源帧号，`D` 为首次击杀反馈的源帧号，`P[i]` 为上述方案时间轴上的源帧时间戳。保留首枪起的 `K` 帧，删去半开区间：

```text
[P[F + K], P[D])
```

本次 60 FPS 素材使用 `K = 3`（约 50 毫秒），首枪可见后直接衔接击杀反馈。这个值可以作为同类素材的起点；按用户要求、帧率和实际闪光持续时间调整。`F + K >= D` 时保留原动作。首枪区间可包含分次点射间的停顿，前提是仍属于已核实的同一次站定交火。

复用已有 `analysis.json`；没有时先 `analyze`。保留原方案，另存为 `analysis.muzzle-flash.json`，只启用本次核准的目标击杀，关闭不符合本次站定条件的其他抽帧项。

| 字段 | 专用方案的值 |
| --- | --- |
| `burst_start` | `P[F]` |
| `safe_start`、`cut_start` | `P[F + K]` |
| `safe_end`、`cut_end` | `P[D]` |
| `cut_points` | `P[F + K : D + 1]`，包含两端可选边界 |
| `enabled` | 仅核准且有有效中间区间的事件为 `true` |
| `reason` | 说明经逐帧复核站定、首枪闪光、保留帧数和击杀反馈边界 |

保留原来的 `media`、击杀 ID、检测时间 `time` 和匹配分数 `confidence`；不要把人工判断写成检测分数。方案中的 `preset` 可记为 `stationary-first-muzzle-flash`，只用于说明已保存的剪接方式，不是可传给 `--preset` 的新选项。

另外保存小型 `review/cut-review.json`：记录 0 起始帧号约定、顺序解码方式、每次的 `F` / `D`、保留帧数、剪接边界及删除时长。当前分析模型不接收任意新增字段，这些复核信息应放在旁文件。录像路径和本次帧号留在任务产物里，不写入分发的 skill。

```text
python "SKILL_DIR/scripts/chouzhen.py" render "OUTPUT_DIR/analysis.muzzle-flash.json" --output "OUTPUT_DIR/first-shot.mp4"
```

使用已有源文件一致性校验；不改写 `media` 来绕过它。复核后修订本次输出、确需覆盖时，沿用 `render --overwrite`。

## 验证实际输出

1. 用 ffprobe 核对分辨率、帧率、音轨和实际时长，再完整解码检查错误。时长应与源时长减去合并后删除区间的总时长相符，允许容器或输出帧量化造成的微小差异。
2. 逐帧查看每个接缝，确认首枪闪光保留帧和首次击杀反馈仍在成片中。需要精确对应时，对源片与成片都顺序解码；变帧率转恒定帧率可能补帧，不能只用“源帧号减去删除帧数”推算输出帧号。
3. 对照接缝附近画面或缓存的缩小图像确认对应关系。有损编码会使像素略有差异；相似度用于定位，不能代替对闪光和击杀提示的观察。

视频与第一条音轨使用相同剪接区间。报告实际处理数、删去时长、成片时长及已完成的检查；没有审听就不声称听感通过。核验完成后清理本次临时帧数组，保留成片、方案和必要的复核记录。
