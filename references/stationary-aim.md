# 停步瞄准剪接

“抽掉站立后的瞄准过程”以开枪或恢复走位作为接回成片的动作。保留移动、每一枪的闪光与后坐力，以及本人击杀反馈。若用户指定从第一枪之后开始删，使用[首枪到击杀流程](first-shot.md)。

## 逐段确定边界

1. 从已有 `analysis.json` 的候选时点往前看完整交火。结合击杀栏新增行和中央反馈去掉重复候选。同一人再次成为受害者时，以这次是否出现新记录为准。保留原始候选 ID。
2. 先看小地图中玩家相对墙角或固定地标的位置。小地图会随视角旋转时，先对齐地图朝向。再看场景里的近处箱沿和远处墙角。抵消转动视角造成的共同位移后，近、远景之间的相对位移能帮助判断横移何时结束。选用场景本身的特征，避开枪模、敌人和 HUD。
3. 把确认站定且正在瞄准的第一帧记作 `S`。逐帧比较本人的枪口，首次出现开火闪光的帧记作 `E`。若先恢复横移，则以重新移动的第一帧为 `E`。删除 **`[S, E)`**，保留 `E`。停步与开枪同帧、仍在减速或遮挡导致无法确认时，保留该段。
4. 两枪之间若有走位，保留完整走位和已经打出的枪，针对下一次停步重新找边界。同一击杀可以对应多段，也可以没有可剪段。若停住后先继续走再开枪，第一次暂停只剪到重新移动前。

用顺序解码的画面编号，从 0 起计。先用缩略图定位，再逐帧看停步、枪口和击杀附近的小窗口。帧号与显示时间戳的对齐方法见[首枪流程中的时间轴说明](first-shot.md#帧号与时间戳必须对应同一张画面)。

## 保存复核明细并导出

在任务目录另存 `cuts.json`。每个已确认的本人击杀占一组，`source_analysis_id` 对应原分析里的 ID。记录该次交火中所有要保留的枪口闪光起始帧，包括移动中开枪的那一发。能确认首次击杀反馈时，填写 `first_feedback_frame`。有效击杀没有可剪段时保留该组并填写 `"removed_intervals": []`。

下面的示例中，玩家第一次停步后又开始横移，第二次停步后开枪。各帧号仅演示文件格式。

```json
{
  "source": "match.mp4",
  "kills": [{
    "source_analysis_id": 2,
    "retained_muzzle_flash_frames": [120, 147],
    "first_feedback_frame": 151,
    "removed_intervals": [
      {"start_frame": 92, "end_frame_exclusive": 98, "first_retained_action": "恢复横移"},
      {"start_frame": 114, "end_frame_exclusive": 120, "first_retained_action": "开枪"}
    ]
  }]
}
```

`source` 可填原分析的 `media.path`，也可填相对 `cuts.json` 的录像路径。复用上次制作的明细时，可直接保留其中的 `source_frames`、时码和汇总字段。修改切点时以源帧号为准，渲染会读原片的显示时间戳重新计算时长。

```text
python "SKILL_DIR/scripts/chouzhen.py" render "OUTPUT_DIR/analysis.json" --aim-cuts "OUTPUT_DIR/cuts.json" --output "OUTPUT_DIR/stationary-aim.mp4"
```

这次导出只应用复核明细里的区间。命令从原片同一时间轴裁剪画面和第一条音轨，并检查区间是否覆盖已标记的开枪、击杀反馈或上一段的首个保留帧。后续微调可另存一份明细，沿用原分析重新导出。

## 核对成片

逐个看接缝。若 `S > 0`，左侧最后一帧应对应源帧 `S - 1`，右侧第一帧应对应 `E` 的枪口闪光或移动动作。逐次确认每一枪及其后坐力、横移和击杀提示仍在。可用顺序解码的缩略画面对齐，再放大枪口和 HUD 复看。

恒定帧率素材可核对原帧数减去删除帧数是否等于成片帧数。变帧率素材按显示时间戳与接缝画面核对。用 ffprobe 检查成片时长、帧率和音轨，并完整解码。交付时分别读取 `candidates`、`kills`、`edited_kills` 和 `cut_intervals`，同时给出实际删除的帧数与时长。
