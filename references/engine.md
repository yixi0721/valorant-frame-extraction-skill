# 引擎与验证

## 维护入口

`scripts/chouzhen_core/` 是随 skill 分发的独立引擎。无需修改原桌面应用；改变这里的代码只影响此 skill。

| 文件 | 职责 |
| --- | --- |
| `detection.py` | 本人高亮头像模板学习、击杀记录跟踪、候选细化、弹药变化分析 |
| `planning.py` | 保留开枪/反馈窗口、按真实 PTS 生成可删区间、预设及帧数调整 |
| `rendering.py` | 按同一时间轴裁剪音视频、接缝淡入淡出、临时文件导出与取消 |
| `media.py` | ffprobe、时间基和源文件参数 |
| `models.py` | 分析数据结构与源文件一致性检查 |
| `engine.py` | 分析流程编排 |
| `../chouzhen.py` | 环境检查、一键运行、修改方案及导出命令 |

识别阶段缩放画面到 1920×1080，在右上角寻找本人击杀记录的高亮边框，再从录像中取得头像模板。被击杀者图像特征用来跟踪记录；记录保持显示或上移不应被重复计数。开头已经可见的记录不算新击杀。

扫描约以 12 FPS 采样，再回到候选区间逐帧匹配 HUD 记录，随后在附近分析弹药数字变化。不要把稀疏采样位置直接作为剪接点，也不要使用固定冷却时间去重而丢掉快速多杀。

当前内置坐标针对标准 16:9 HUD。新录制尺寸可先验证归一化后的布局；裁切、超宽屏、观战及覆盖层需要实际画面依据，不能仅靠降低匹配阈值宣称支持。

## 验证证据与局限

已知回归样片为一段约 25.045 秒、1920×1080、名义 60 FPS 的第一视角录像，包含手枪击杀及步枪三连杀。人工核对的四个 HUD 记录时间约为 6.06、17.58、19.42、20.28 秒；测试允许 0.12 秒定位误差。自然模式仅压缩第 2、4 次的较长连射，共约 0.50 秒。

该样片未随 skill 分发。以上数值只用于这份原始样片的回归测试，不是对新录像的预设，也不能据此声明通用识别准确率。

另一次约 44.096 秒、1920×1080、名义 60 FPS 的第一视角录像，用[首枪闪光流程](first-shot.md)逐帧复核了 4 段站定交火，保留每次首枪起的 3 帧，删去约 2.850 秒，成片约 41.246 秒。核验包括完整解码及成片中首枪保留帧、首次击杀反馈帧与源画面的对应关系；不代表完成了审听。

这次发现弹药检测会漏掉同一次交火中更早的点射，随机跳转取帧也可能与实际帧号相差 1 帧，最终以顺序解码和 PTS 校准。该结果来自 Agent 的逐帧复核，不是新增自动检测器或通用阈值；新录像仍需自己的证据，也不能用它替代原始回归样片。

## 执行测试

测试只需额外安装 pytest。使用与处理录像相同的解释器，避免 GUI 依赖：

```text
python -m pip install pytest
python -B -m pytest "SKILL_DIR/scripts/tests" -q -p no:cacheprovider
```

默认跳过原始样片测试。只有拿到上述同一份录像，才设置 `CHOUZHEN_REFERENCE_VIDEO` 为其绝对路径；不要对任意用户录像设置这个变量。测试使用临时目录创建合成媒体，覆盖记录移动和数量不变时的新击杀、源帧边界、取消、覆盖保护及导出音画时长。

调整识别器后，还需用新素材的人工核对时间验证漏检、重复和误检。测试通过只说明对应行为已验证，不能代替对剪接观感和听感的实际检查。
